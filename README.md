## 1. What is Vaani-AI?

**Vaani-AI** (वाणी AI) is an open-source, production-grade realtime conversational voice assistant. Traditional voice bots are awkward "walkie-talkie" chatbots: you click a mic, record 5 seconds of audio, wait for a server roundtrip, and listen to a robotic monologue you cannot interrupt.

**Vaani-AI changes that completely:**
* **Continuous Realtime Voice:** Fluid, bidirectional conversation over WebRTC.
* **Starts Speaking Immediately:** Begins audio synthesis on the very first tokens/clauses generated by the LLM before the full response is finished.
* **Instant Barge-In / Interruption:** Interrupt the assistant at any time mid-sentence; it immediately cuts off audio playback and switches back to listening.
* **Native Multilingual (English, Hindi, Hinglish):** Seamlessly understands and speaks English, Hindi, and colloquial Hinglish (e.g., *"React hooks kaise kaam karte hain, simple shabdon mein samjhao"*).
* **Vendor-Neutral & Pluggable:** Swap any component (VAD, STT, LLM, TTS) between lightning-fast cloud APIs or fully self-hosted local open-source models.

## 2. Interactive Voice States

Vaani-AI synchronizes 6 visual voice states across client and server:

```
[ IDLE ] ──> [ CONNECTING ] ──> [ LISTENING ] ──> [ THINKING ] ──> [ SPEAKING ]
   ^                                   ^                                  │
   │                                   └─────── (Barge-in / Done) ────────┘
   └─────────────────────────── [ ERROR ]
```

| State | Indicator | Audio Flow | Description |
| :--- | :--- | :--- | :--- |
| **`IDLE`** | Gray | Off | Disconnected or standing by; ready to start. |
| **`CONNECTING`** | Amber | Handshake | Fetching token, negotiating WebRTC ICE candidates. |
| **`LISTENING`** | Green | Inbound | Microphone streaming; VAD detecting speech; STT live. |
| **`THINKING`** | Violet | Internal | User speech turn complete; LLM generating tokens / executing tools. |
| **`SPEAKING`** | Cyan | Outbound | TTS streaming synthesized audio to client speaker. |
| **`ERROR`** | Red | Halted | Network or model failure; automatic retry backoff. |

## 3. System Architecture

Vaani-AI uses a modular, low-latency streaming pipeline orchestrated over LiveKit WebRTC:

```
Browser (React + TypeScript UI)
       │  ▲
       ▼  │  (Opus WebRTC Audio Stream)
 LiveKit SFU (Realtime Audio Transport)
       │  ▲
       ▼  │  (Low-Latency Worker Dispatch)
 Python Voice Agent Worker
 ┌────────────────────────────────────────────────────────┐
 │ 1. Silero VAD (Speech boundary detection)              │
 │ 2. Deepgram Nova-2 / Qwen3-ASR (Streaming transcript)  │
 │ 3. Groq / OpenAI / Ollama (Streaming token generation) │
 │ 4. Cartesia / ElevenLabs / Qwen3-TTS (Streaming audio) │
 └────────────────────────────────────────────────────────┘
```

### Pluggable Provider Interfaces

| Component | Default Cloud Adapter | Local / Open-Source Alternative | Latency Target |
| :--- | :--- | :--- | :--- |
| **VAD** | Silero VAD (ONNX, embedded) | WebRTC VAD | < 30ms |
| **STT** | Deepgram Nova-2 (WebSocket) | Qwen3-ASR / Whisper (GPU/local) | ~150ms - 250ms |
| **LLM** | Groq (Llama-3.3 70B) / OpenAI (GPT-4o-mini) | Ollama (Qwen2.5 / Llama 3.2) / vLLM | ~150ms - 350ms (TTFT) |
| **TTS** | Cartesia Sonic (WebSocket) / ElevenLabs | Qwen3-TTS / Kokoro / Piper | ~80ms - 200ms (TTFA) |

### End-to-End Latency Budget

```
[User stops speaking]
  ├── 0ms - 100ms   : VAD detects end of speech turn
  ├── 100ms - 250ms : STT finalizes phrase transcript
  ├── 250ms - 450ms : LLM generates first tokens (TTFT)
  ├── 450ms - 650ms : TTS synthesizes initial clause (TTFA)
  └── 650ms - 750ms : LiveKit packet arrives at browser speaker
[Agent begins speaking]
```
**Total Target Latency: < 800ms**

## 4. Hardware Sizing & Deployment Tiers

You do **not** need a high-end GPU to run or develop Vaani-AI:

* **Tier 1: Cloud-Assisted (Recommended for Standard Laptops)**
  * **Hardware:** Any modern dual-core CPU, 8GB RAM, no GPU.
  * **Stack:** LiveKit Cloud, Deepgram STT, Groq/OpenAI LLM, Cartesia TTS.
  * **Latency:** ~500ms - 750ms.
* **Tier 2: Hybrid (Local LLM + Cloud Speech)**
  * **Hardware:** 6-core+ CPU, 16GB RAM or Apple Silicon / 6GB VRAM GPU.
  * **Stack:** Local Ollama (`llama3.2` or `qwen2.5`) + Deepgram + Cartesia.
  * **Latency:** ~900ms - 1300ms.
* **Tier 3: Fully Self-Hosted / Offline**
  * **Hardware:** Dedicated NVIDIA GPU (16GB+ VRAM e.g. RTX 3090/4090) or 32GB+ Unified Memory Mac.
  * **Stack:** Self-hosted LiveKit, Whisper/Qwen3-ASR, local Ollama/vLLM, local Qwen3-TTS/Kokoro.

## 6. Quick Start & Local Installation

### 6.1 Prerequisites
* Node.js v18+ & npm v9+
* Python 3.10+ (Python 3.12 recommended)
* A free [LiveKit Cloud](https://cloud.livekit.io) account (or local server)

### 6.2 Configure Environment
```bash
cp .env.example .env
```
Fill in your `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, and speech/LLM API keys.

### 6.3 Running Components

#### Backend Token Service (`backend/`)
```bash
cd backend
npm install
npm run dev
# Running on http://localhost:5000
```

#### Python Voice Agent (`agent/`)
```bash
cd agent
python -m venv .venv
# Windows: .venv\Scripts\Activate.ps1 | macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python main.py dev
```

#### Frontend Client (`frontend/`)
```bash
cd frontend
npm install
npm run dev
# Running on http://localhost:5173
```
